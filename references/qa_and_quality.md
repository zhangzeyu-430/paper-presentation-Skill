# 追问与质量标准

## 老师追问与回答（最小要求）

至少 12 问，按 5 类分组：
- 基础理解类
- 方法机制类
- 实验设计类
- 局限批判类
- 课题迁移类

每题必须包含：
- 问题
- 老师为什么会问
- 回答思路
- 现场可直接说的回答

## 默认课题迁移增强（用户未提供背景时）

按论文任务类型做迁移评估，不绑定某一具体模型名：
- 数据特性迁移：高噪声、异常值、长尾、分布漂移
- 任务迁移：预测/分类/检测/生成在目标课题中的可用性
- 方法迁移：主干架构、损失函数、特征工程、训练策略可复用部分
- 实验迁移：评估指标、对照设置、消融设计可借鉴部分

## 禁止行为

- 只输出摘要
- 只输出提纲
- 只报数字不解释含义
- 只夸论文不讲局限
- 信息不全时假装确定

## 交付前质量检查

1. 没读过论文的人听完能理解主线
2. 读过论文的人不会觉得浅
3. 用户可以直接照稿汇报
4. 方法页讲清机制，不是概念堆砌
5. 实验页讲清证据链，不是报数字
6. 追问部分覆盖真实质疑场景
7. 给出可执行的课题迁移建议

## 组会成品质检标准

生成结果必须像“可以上台讲的组会 HTML deck”，而不是论文摘要、黑白讲义或自动排版草稿。

必须满足：
- 第 1 页必须是完整论文标题封面，包含题目、作者/机构、会议/年份、任务领域和一句话贡献
- 首页必须像学术 PPT 封面：logo/机构标识、居中大标题、中文副标题/汇报主题、汇报人、日期、底部主题色信息条；不能是普通左右两栏内容页
- 最后 1 页必须是谢谢 / Q&A / 重要参考资料页，包含论文链接、代码链接、核心引用或可讨论问题
- 每页都有一个明确判断：本页到底想让听众相信什么
- 每个核心判断都有证据：图、表、公式、实验数字或论文原文依据
- 每页有足够可见解释：除封面/总结外，必须有正文导入、证据解读、图表说明和 takeaway，不能把解释全部藏在 notes
- 可见解释必须是论文内容本身，不能把“怎么设计页面、怎么读图、为什么这样排版”的生成器说明放进 HTML
- 方法页能讲出机制：输入是什么、做了什么、输出是什么、为什么有用
- 实验页能讲出证据链：比较对象、关键数字、证明的 claim、可能替代解释
- 批判页敢讲不足：适用边界、复现风险、缺失实验、业务迁移风险
- 逐字稿能自然承接 PPT：不是照读 bullet，而是解释 bullet 背后的逻辑
- 视觉上必须有主题色、层级背景、关键数字强调、图表重绘和清晰布局；黑白文档风直接判失败
- 图表和表格必须来自论文真实内容，不能用无关示意图或编造数字补空
- 页面不得大面积留白；任何高度超过页面 30% 的卡片都必须承载真实正文、图表、表格或公式
- 方法页视觉必须贴合论文原图/公式/方法段落；泛化流程图不能作为核心视觉
- 核心论文图必须裁剪到 Figure/Table/公式局部；整页论文截图缩略图直接判失败
- 整体观感必须接近日常组会 PPT；网页 dashboard、信息面板、论文讲义式页面直接判失败

## HTML Deck 专项 QA（必做）

在 HTML deck 交付前，至少完成一次以下循环：
1. 生成 `*_组会汇报.html`
2. 运行 `scripts/validate_html_deck.py` 自动检查（slide 数、控件、首页/结束页、图片路径、整页截图风险、元话语）
3. 若有 PDF，运行或引用 `scripts/inspect_pdf_assets.py` 的候选结果，确认核心图表不是凭空选择
4. 执行文本抽检（标题、占位词、关键数字、来源依据）
5. 检查 `asset_manifest.json` 与 `deck_plan.json`：每页证据必须能回溯到素材 `id`
6. 浏览器逐页视觉抽检（全页，不只抽样）
7. 若发现问题，优先修改 `*_HTML展示稿.md`、`*_deck_plan.json`、裁图素材或 HTML 版式
8. 修复后再复检

推荐命令：

```bash
python skills/paper-presentation/scripts/validate_html_deck.py outputs/{论文简称}_组会汇报.html --md outputs/{论文简称}_HTML展示稿.md --manifest outputs/{论文简称}_asset_manifest.json --plan outputs/{论文简称}_deck_plan.json
```

若发现以下问题，必须重做对应页面：
- 页面正文是逐字稿口语摘抄
- 页面缺少关键结论/关键证据
- 页面只有短 bullet，没有正文导入、证据解读和图表说明
- 缺少 `asset_manifest.json` 或 `deck_plan.json`，或页面证据无法回溯到素材 `id`
- 连续 3 页使用同一版式，导致看起来像网页模板批量生成
- 第 1 页不是论文标题封面
- 首页没有 PPT 封面结构，或被做成左右两栏内容页
- 最后 1 页不是谢谢 / Q&A / 重要参考资料页
- 文字拥挤、重叠、溢出或对比度过低
- 大面积空白卡片或空面板
- 使用整页论文截图作为核心图，未裁剪、未高亮、不可读
- 翻页/讲稿控件遮挡正文、页码、来源、takeaway 或图表
- 图表无来源或数字不可追溯
- 标题含“第X页”前缀或占位文案残留
- 使用无论文依据的装饰图、通用图标或随机图形充当核心视觉
- 键盘翻页、页码或 notes 数据缺失
- 页面只是黑白文字、普通 Markdown 风格或浅色卡片堆叠
- 页面有数字但没有解释该数字证明什么
- 页面有图但没有说明该图对应论文哪个 claim
- 页面可见区域出现元话语：`封面把`、`表格只保留`、`示意图把`、`读图时`、`听众应该`、`观众应该`、`这个结果支持`、`这一页`、`本页`、`页面用于`

## 失败后修复路径（强制）

发现问题时，必须按下列路径回退修复：

- 文字溢出：回到 `*_HTML展示稿.md`，拆页、压缩长标题、重排解释段落；不得靠缩到不可读字号或删成空洞短句解决。
- 页面太空：回到素材盘点表，补真实数字、模块输入输出、公式含义或证据结论；不得加装饰图填空。
- 图片无关：回到素材盘点表重新选论文图，或用论文表格/公式重绘；不得使用通用图标替代。
- 内容太浅：回到 claim 与证据链，补“为什么有效”和“实验证明了什么”。
- 只有 bullet：补正文导入、证据解读、图表说明和 takeaway；bullet 只能做辅助。
- 元话语外泄：把页面设计说明、读图顺序、讲者提示移入 notes；可见正文改写为论文事实、真实数字、变量标注或结论短句。
- 视觉不贴合论文：回到素材盘点表，优先使用论文原图截图/局部高亮/忠实重绘；不能用泛化示意图补位。
- 整页截图问题：用 PDF 裁剪工具裁出 Figure/Table bounding box；图太复杂则拆成多页局部放大。
- PPT 观感问题：重做封面、页眉、角标、底部色条和主图布局，取消网页式双栏大白框。
- 实验页像报表：只保留支撑 claim 的 3-5 个关键数字，并写出结论含义。
- 方法页像概念堆砌：重画输入 -> 模块 -> 输出流程，并给每个模块写“解决什么问题”。
- 页面太丑或太简陋：重做视觉系统，补主题色、背景层次、claim 区、证据区、图表/数字强调。
- 内容没含金量：回到素材盘点和 claim 证据链，补真实图表、关键数字、机制解释和批判判断。
- 逐字稿像翻译摘要：重写为第一人称讲解，补动机、直观解释、证据解读和转场。
- 追问太泛：围绕公平性、消融充分性、复现难点、适用边界和课题迁移重新生成。
