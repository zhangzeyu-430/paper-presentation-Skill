# HTML Deck 与逐页稿规范

## 页数策略

- 10 分钟：8-10 页
- 15 分钟：10-12 页
- 20 分钟：12-15 页
- 默认第 1 页必须是封面页，展示论文完整标题、作者/机构、年份/会议、任务领域、汇报主题和一句话贡献；不得直接从动机页开始。
- 若用户要求“组会讲解准备资料/直接拿来讲”，优先生成 12-16 页讲解型 HTML，而不是压缩成 8-10 页要点 deck。

## 每页必备字段（页面结构阶段）

- 页标题（禁止“第X页：”前缀）
- 页面类型（从“页面类型库”中选择）
- 本页要解决的问题
- 页面应放内容（图/表/公式/文字）
- 核心讲法
- 预计讲解时间
- 与下一页转场逻辑

页面结构必须同时写入 `deck_plan.json`，并引用 `asset_manifest.json` 中的素材 `id`。不得先写 HTML 再倒推素材来源。

## 组会叙事主线（强制）

HTML deck 必须围绕一条可讲清的研究判断线展开，而不是按论文小节机械搬运。

默认叙事线：
1. 这篇论文想解决什么痛点
2. 作者认为旧方法为什么不够
3. 核心设计到底改了哪里
4. 这些设计为什么可能有效
5. 实验是否真的支撑这些 claim
6. 这篇工作的价值、局限和可迁移点是什么

每页必须能回答上述其中一个问题；不能回答任何问题的页面应删除或合并。

## 页面类型库（强制）

生成页面结构时，每页必须选择一种页面类型，并遵守对应内容要求：

- 封面页：必须采用“学术 PPT 首页”版式，而不是左右两栏内容页。包含学校/实验室/机构 logo 或文字标识、英文论文题目大标题、中文副标题/汇报主题、作者与机构、汇报人、日期、底部主题色横条；必须是第 1 页。
- 论文定位页：一句话贡献 + 任务定义 + 主要结论；适合第 2 页。
- 问题动机页：痛点链路或对比卡片；禁止泛泛讲领域背景。
- 方法总览页：输入 -> 核心模块 -> 输出流程图；必须标出数据流。
- 核心模块页：模块输入、关键操作、输出、解决的问题；必须有公式/流程/模块卡片之一。
- 主实验页：3-5 个关键数字或局部表格；必须写清“证明了哪个 claim”。
- 消融页：删除组件后的变化 + 贡献解释；必须对应具体模块。
- 鲁棒/泛化页：跨数据集、跨 horizon、少样本或迁移结果；必须讲适用边界。
- 批判页：证据充分性、复现风险、局限和替代解释；禁止只写优点。
- 迁移启发页：可复用部分、不可直接搬的部分、落地验证建议。
- 总结页：3 个 takeaway + 1 个局限 + 1 个后续问题。
- 结束页：谢谢 / Q&A / 重要参考资料；必须是最后 1 页。包含论文题目短名、代码链接或论文链接、2-4 条重要参考资料、可讨论问题。不得只写“谢谢”两个字。

若论文缺少某类证据，不得硬凑页面；应在批判页说明“不确定/论文未充分报告”。

## 页面内容密度规则

- 每页最多 1 个核心结论，但必须讲清“为什么”和“证据是什么”。
- 每页可见正文必须是“短段落 + 少量 bullet + 图表说明”的组合，禁止只有标题和 bullet。
- 普通内容页可见正文建议 160-280 个中文字符；方法/实验重点页建议 220-420 字；封面页和结束页可少于 120 字。更详细解释必须进入 notes/逐字稿，不得把 HTML 做成论文讲义网页。
- 每页至少包含 2 个解释性文本块：`背景/问题解释`、`机制解释`、`证据解读`、`局限解释` 中任选两个。
- bullet 只用于列举关键点，每页 3-5 条；每条建议 18-42 个中文字符，最长不超过 56 个中文字符。
- 每个视觉模块必须有 1 段 40-100 字图表解读，说明“这张图/表证明了什么”，不能只放图名。
- 1 个主要图/表/流程图或 2-3 个小证据模块；视觉区不得出现大面积空卡片。
- 页面正文禁止出现占位指令（如“本页要放什么/建议放什么”）
- 同一布局连续使用不超过 2 页，必须有布局变化
- 若页面空白面积明显超过 35%，必须补充真实论文内容、拆换布局或缩小无内容容器；不得用空白卡片制造“高级感”。
- 反过来，若页面像网页信息面板、左右两栏大白框、正文段落过长、控件遮挡页脚，也视为失败。HTML 的目标是“PPT 风格幻灯片”，不是 dashboard 或网页文章。

## 学术 PPT 视觉目标（强制）

HTML 虽然是技术载体，但视觉必须按 PPT 成品设计：

- 使用固定 16:9 `.slide-stage` 或 `.slide-canvas`，内容在画布内排版；不要把整个浏览器窗口当作无限网页画布。
- 页面应有 PPT 式页眉/章节编号/角标 logo/主题色横条之一，形成连续版式身份。
- 封面页必须接近日常组会 PPT：首页居中大标题、中文副标题、顶部或右上 logo、底部深色信息条、汇报人和日期；禁止左右两栏、卡片堆叠、结果看板式封面。
- 内容页推荐结构：主体图/表/流程占主视觉 + 右侧/下方 3-5 条结论；不要把所有页面做成“左正文 + 右证据”的平均两栏，也不要出现两个巨大的等宽空白面板。
- 视觉控件不得遮挡幻灯片内容。上一页/下一页/讲稿按钮应放在画布外、半透明自动隐藏，或预留独立控制区；不得覆盖页码、takeaway 或正文。
- 不使用悬浮在页面底部中间的醒目 takeaway 条；它容易遮挡主图、来源和页码。核心结论应并入 claim、侧边结论卡、图上标签或 speaker notes。
- 字号与密度按投影阅读设计：标题 28-44px，正文 18-24px，注释 13-16px；不要为了塞内容把字号压小，也不要把大段解释放进页面。
- 每页最多 2 个主要内容区。若需要 3 个以上面板，必须形成清楚的编号/流程/分组，而不是平均摊开。
- 如果连续多页虽然 `layout_pattern` 名称不同，但视觉骨架都是同一个左右两栏 grid，视为版式失败。

失败形态：
- 看起来像网页 dashboard：大面积浅色圆角卡片、双栏正文、右下角悬浮按钮覆盖内容。
- 看起来像模板化报告：claim 横条 + 左侧解释段 + 右侧卡片/图表 + 底部重复 caption，每页只是换文字。
- 看起来像被遮挡的 PPT：底部结论条压住主图、来源、页码或正文。
- 看起来像自动排版讲义：标题 + 段落 + bullet + 证据框。
- 看起来像论文 PDF 预览器：直接展示整页论文截图，图太小不可读。
- 看起来不像 PPT 首页：没有 logo/汇报信息/日期/底部信息条，只是普通内容页。

## `HTML展示稿.md` 写法（强制）

`HTML展示稿.md` 是最终 HTML deck 页面正文的唯一来源，必须写成“观众可读的论文内容层”，不是提纲，也不是逐字稿。

重要：HTML 不是极简 PPT。它应当像“可投屏的论文讲解讲义”：观众不听口播，只看页面，也应能理解本页的核心逻辑。

更重要：观众页不能出现生成器/讲者视角的解释，例如“封面把……放在同一屏”“表格只保留……”“示意图把……分开画”“这个结果支持……”“读图时应该……”等。这类文字只能进入 `图表设计说明`、`讲者提示`、`逐字稿` 或 QA，不得渲染到 HTML 可见区域。

每页格式：

```md
## 第 1 页：页面标题
页面类型：定位页 / 动机页 / 方法总览 / 模块深挖 / 实验设计 / 主结果 / 消融 / 批判 / 迁移
本页核心判断：一句话说明本页想让听众相信什么
视觉元素：论文原图 Figure 1 / 表格重绘 Table 2 / 方法流程图 / 对比卡片
布局建议：左右两栏 / 上图下文 / 三卡片 / 结果表格+结论
来源依据：论文 Figure X / Table Y / Section Z
观众可见正文：用 60-140 字直接讲论文内容、方法机制或实验结论；禁止写页面设计意图。
关键要点：
- 结论：……
- 证据：……
- 机制：……
- 局限：……
证据解读：用 60-140 字直接解释论文图表、公式或数字的含义；禁止写“这个图想表达/这页要说明”。
图表标注：写可直接贴在图上的短标签、变量名、箭头说明、表格列名或高亮注释；禁止写页面设计说明。
图表设计说明：给生成器/讲者看的布局说明，不进入 HTML 可见正文。
讲者提示：给 notes 的讲解提示，不进入 HTML 可见正文。
页尾 takeaway：一句话收束本页。
```

生成规则：
- `观众可见正文`、`关键要点`、`证据解读`、`图表标注`、`页尾 takeaway` 可以进入 HTML 可见正文。
- `视觉元素`、`布局建议`、`图表设计说明`、`讲者提示`、`页面目的`、`核心讲法`、`转场逻辑` 只能进入 notes/逐字稿/QA，严禁进入 HTML 可见正文。
- 禁止在 HTML 可见区域出现元话语：`封面把`、`表格只保留`、`示意图把`、`读图时`、`这个结果支持`、`这一页`、`本页`、`页面`、`观众应该`、`听众应该看`、`用于帮助`、`避免`。
- bullet 不能是 HTML 正文的唯一来源；若生成器只读取 `- ` 行，必须先修改生成逻辑或手写 HTML，不能交付残缺页面。
- `视觉元素/布局建议/来源依据` 必须写成非 bullet 元数据。
- `页面类型` 与 `本页核心判断` 必须写成非 bullet 元数据，供 HTML 生成使用。
- 禁止把“页面目的、页面内容建议、讲解策略、建议放图”等过程说明写成 bullet。
- 若某页没有合适原图，必须使用“论文公式/论文表格重绘/基于原图的忠实流程重绘/论文原文短摘录卡”之一补足视觉结构；不得使用泛化示意图凑版面。
- 实验页至少包含 1 条真实数字或表格结论；方法页至少包含 1 条模块输入输出或关键公式含义。
- 若 bullet 过长，先改写展示稿，而不是依赖 CSS 缩小到不可读字号。
- 如果某页无法写出至少 2 个解释性文本块，说明论文理解不够，必须回到原文继续读，而不是生成空页面。

## 观众层 / 讲者层 / 元数据边界（强制）

生成 HTML 前必须把每页内容分成三层：

- 观众可见层：论文事实、作者 claim、方法变量、公式含义、真实数字、图表标注、结论短句。
- 讲者层：为什么这样讲、读图顺序、转场句、追问回答、详细解释，写入 `aside.notes` 和逐字稿。
- 生成器元数据：视觉元素选择、布局建议、页面目的、素材来源、图表设计说明，只能留在 `HTML展示稿.md` 或 QA。

观众可见层禁止出现以下类型文字：
- 页面设计说明：如“封面把题目、任务、关键词放在同一屏”。
- 生成决策说明：如“表格只保留 Table 8 的关键结论”。
- 示意图说明废话：如“示意图把短期预测和长期预测分开画”。
- 讲者动作说明：如“读图时先看左边”“让听众建立预期”。
- 空泛支撑话术：如“这个结果支持某某观点”，除非同时给出真实数字、对象和机制。

改写方式：
- 坏：表格只保留 Table 8 的关键结论：4-head 最稳。
- 好：Table 8：4-head 在 35 个场景中取得 21 个 MSE 最优、20 个 MAE 最优；16-head 未继续带来稳定收益。
- 坏：示意图把短期预测和长期预测分开画。
- 好：H=96 更依赖近期局部波动；H=720 更依赖周期/趋势信息，gating 学习时域与频域的动态权重。
- 坏：封面把题目、任务、方法关键词和核心结果放在同一屏。
- 好：T3Time: Tri-Modal Time Series Forecasting via Adaptive Multi-Head Alignment and Residual Fusion；MTSF；MSE -3.28%，MAE -2.29%。

## 页面信息架构（强制）

每页 HTML 不得只是标题 + bullet + 卡片。必须具备一个明确的信息架构：

- `Claim`：本页核心判断，用醒目的结论条或标题副标呈现。
- `Evidence`：图、表、公式、真实数字或论文原文依据。
- `Explanation`：解释证据为什么支持 claim，不得只报数字。
- `Takeaway`：本页听众应带走的一句话，可与 Claim 合并。
- `Context`：除封面和总结外，每页必须有 60-120 字上下文说明，解释为什么要看这一页。
- `Figure/Table Reading`：出现图表时必须告诉听众读图顺序、关注区域和结论。

注意：`Context` 和 `Figure/Table Reading` 在 HTML 可见层中必须改写为论文内容本身，不得出现“为什么要看这一页”“读图顺序”“听众应该看哪里”等措辞。讲解顺序写入 notes。

不同页面类型的最低要求：
- 动机页：必须有“旧方法为什么不够”的对比结构。
- 方法页：必须有输入、操作、输出和解决的问题。
- 实验页：必须有比较对象、真实数字、证明的 claim。
- 消融页：必须有完整模型、去除模块、性能变化、贡献解释。
- 批判页：必须有证据不足、适用边界或替代解释。
- 迁移页：必须有可借鉴、不可直接搬、需要补做的实验。

## HTML Deck 页面规范（强制）

- 使用单文件 HTML，内嵌 CSS/JS；除论文截图或本地图片外，不依赖外部网络资源。
- 每页是一个 16:9 `.slide` 容器，适配 1366x768、1920x1080 和常见投影比例。
- 推荐实现为 `body` 居中承载固定比例 `.slide-canvas`：`width:min(100vw, 177.78vh); height:min(100vh, 56.25vw); aspect-ratio:16/9;`，再在内部进行 PPT 式绝对/网格排版。不要让 slide 高度直接等于整个滚动网页内容。
- 支持键盘翻页：右箭头/空格下一页，左箭头上一页，Home/End 跳转首尾。
- 页面右下角显示页码；不要把页码放入标题。
- notes 可放在隐藏面板、`<aside class="notes">` 或页面数据区，不能遮挡观众视图。
- CSS 必须限制文本框高度、行高和最大宽度；任何正文溢出都视为失败。
- 图表可用 HTML table、CSS grid、SVG、canvas 或本地截图实现；优先重绘关键数字表，避免塞入不可读整页大表。
- 方法流程图优先用 HTML/CSS/SVG 重绘，确保模块名、箭头和变量可读。
- 论文原图难以抽取时，可以用“论文页截图 + 高亮框”或“基于论文内容重绘”替代，但必须标注来源。
- 方法页的重绘图必须贴合论文原图/公式：保留原论文模块名、变量名、连接关系和输入输出。不得只画“历史序列 -> 模块名 -> Decoder”这类泛化流程。
- 若论文有 Figure 1/Figure 2/Figure 6 等核心图，必须优先使用原图截图、局部截图+高亮框，或忠实重绘。只有在原图完全不可读时，才允许抽象重绘。

## 论文图片裁剪规范（强制）

禁止把整页论文截图当作核心图片放进幻灯片，除非该页本身就是封面或参考资料页。

必须执行：
- 从 PDF 提取图片时，优先裁剪到 Figure/Table 的 bounding box，保留 caption 或在 HTML 中重写 caption。
- 若自动裁剪失败，至少手动/脚本裁掉页边距和无关正文，只保留图、表或局部方法结构。
- 裁剪后的图在页面中宽度或高度应占对应视觉区的 70% 以上，图中文字应在投影尺寸下可读。
- 若原图过复杂，使用“局部截图 + 高亮框 + 放大解释”拆成多页，而不是整张塞入一页。
- Table 不直接截图整页；应重绘关键行列，保留真实数字和表头。

整页截图判失败：
- 图片中正文栏、页眉页脚、无关段落占比超过 30%。
- Figure/Table 主体占图片面积小于 60%。
- 投影下图中文字不可读。
- 图片只是论文一页缩略图，没有裁剪、高亮或局部放大。

## 视觉设计系统（强制）

HTML deck 必须像正式组会成品，不得是黑白文档式页面。

视觉风格要求：
- 必须定义完整 CSS 设计系统：背景、正文、弱文本、主色、强调色、警示色、面板色、边框色、阴影。
- 禁止纯白底黑字贯穿全篇；必须使用有层次的背景、色块、结论条、表格强调色和模块色。
- 每篇论文选择一种明确主题色，但不能全篇只有一个颜色；至少包含主色、辅助色、警示色和中性色。
- 页面背景可以使用柔和渐变、细网格、浅色分区或页眉色带，但不得使用无意义装饰图。
- 卡片边框半径不超过 8px，阴影克制，保证学术汇报感。
- 字体层级必须清楚：标题、副标题/claim、正文、图注、来源。
- 关键数字必须视觉突出，如大号数字卡、强调色、迷你表格或条形图。
- 所有图表必须有图注或来源行；来源行不能替代正文解释。
- 内容区必须真实填充。任何高度超过页面 30% 的卡片都必须包含正文、图表、表格或公式，禁止空白大面板。

布局要求：
- 至少使用 5 种页面版式，避免 10 页都是左右两栏。
- 推荐版式：封面信息卡、问题对照、流程总览、模块剖面、数字看板、结果表格、消融矩阵、可解释性图、批判雷达/清单、迁移路线图。
- 生成页面结构时必须参考 [layout_patterns.md](layout_patterns.md)，并在 `deck_plan.json` 的 `layout_pattern` 字段记录所选版式；HTML 必须体现版式差异，不能所有页面共用同一个 `.grid` 两栏骨架。
- 每页必须有视觉重心；不要把所有元素平均摊开。
- 同一布局连续使用不超过 2 页。
- 若页面看起来像普通 Markdown 渲染或黑白讲义，视为失败，必须重做视觉层。

## 展示要点反例（强制参考）

禁止空泛 bullet，必须把“对象、结论、证据/机制/影响”写完整。

```md
坏：性能显著提升
好：ETTh1-96 MSE 下降，短期预测收益明确

坏：提出多模态融合框架
好：时间/频域/Prompt 分别补足局部、周期、语义信息

坏：消融证明模块有效
好：移除 CMA 后对齐变弱，性能下降支撑模块贡献

坏：方法具有泛化能力
好：跨多个 horizon 保持优势，说明收益不依赖单一步长

坏：存在一定局限
好：真实业务漂移未验证，部署稳健性仍不确定
```

## 可视化与版式规则（强制）

- 优先主图/主表/主数字看板布局，避免单列长文本；两栏图文只能作为少数页面使用，不得成为默认模板。
- 文本框必须保留安全边距，禁止触边
- 禁止对象重叠遮挡（文字与图形、图形与图形）
- 图表标题、坐标、图例必须完整可读
- 颜色不能纯白底黑字一路到底，需使用主题色与层级背景
- 视觉元素优先来源：论文原图 > 论文表格重绘 > 基于论文数字重建图
- 方法页视觉优先级：论文原图局部截图 + 高亮框 > 忠实 SVG/HTML 重绘原图结构 > 公式/变量关系图 > 抽象示意图。抽象示意图必须作为最后选择，并在 QA 中说明原因。

## 防溢出规则（强制）

- 单页 bullet 不超过 6 条；两栏图文页不超过 5 条。
- 单页解释段落不超过 4 段，每段 40-120 字；超过则拆页。
- bullet 中不要连续堆叠 3 个以上长英文术语；必要时将英文缩写放到括号内。
- 标题最长不超过 22 个中文字符；超长标题必须压缩为“对象 + 结论”。
- 生成 HTML 后必须抽检所有页面；只要出现文字触边、被裁切、遮挡或压到图上，就回到 `HTML展示稿.md` 重写该页。
- 不得用减小到不可读字号的方式解决溢出；正文推荐 15-19 pt，最低不小于 13 pt。
- 不得为了避免溢出而删成空洞短句；应优先拆页、换布局或改成双层信息结构。

## 方法页要求

- 用流程框表达输入、模块、输出
- 解释每个模块解决什么问题
- 标出关键变量或关键公式
- 禁止纯文字堆砌

## 实验页要求

- 不照搬全表
- 只提取最能支撑贡献的结果
- 明确写出“这个实验证明了什么”
- 至少 1 页呈现消融/贡献来源
- 至少 1 页含真实数字对比（不能只写“显著提升”）

## 逐页稿格式（每页固定）

- 页面目的
- 页面内容建议
- 逐字稿
- 这一页老师可能会问
- 简短回答
- 转场句

## 逐字稿质量要求

- 中文、第一人称、自然口语
- 每页不少于 250 字；重点页不少于 400 字
- 不是摘要翻译，必须解释“为什么这样设计/结果说明什么”
- 必须可直接开口讲
