# 输出合同（固定 7 段）

每次输出必须包含以下 7 个一级部分：
1. 论文精读卡片
2. 核心 claim 与证据链
3. 方法机制拆解
4. 实验逻辑拆解
5. 论文素材盘点与组会页面结构
6. 逐页汇报逐字稿
7. 老师可能追问与回答

## 1) 论文精读卡片（最小字段）

- 论文标题、作者、会议/期刊、年份、类型、领域、关键词
- 一句话总结（问题 + 方法 + 结果）
- 论文主线 9 问：研究对象、核心问题、重要性、已有不足、作者思路、为何有效、实验如何证明、不足、对用户启发

## 2) 核心 claim 与证据链

识别 3-5 个 claim。每个 claim 必须包含：
- 作者想证明什么
- 对应方法设计
- 对应实验或图表
- 结果说明什么
- 证据是否充分
- 汇报时怎么讲

## 3) 方法机制拆解

必须讲清：
- 输入、输出、整体流程、模块、模块作用、连接方式、训练目标、推理方式

每个核心模块必须讲清：
- 解决什么问题
- 没有该模块会怎样
- 怎么做（输入/输出/关键操作）
- 直观理解、优点、局限
- 汇报口语讲法

## 4) 实验逻辑拆解

必须覆盖：
- 数据集、任务、输入输出长度、baseline、指标、公平性、消融、效率、泛化/迁移
- 关键实验解释：证明目标、对比对象、结果含义、对应 claim、替代解释、汇报重点
- 实验批判：公平性、baseline 强度、消融完整性、指标充分性、场景代表性、成本报告、失败案例

## 5) 论文素材盘点与组会页面结构

在生成 HTML deck 页面前，必须先列出“论文素材盘点表”。该表是后续 `HTML展示稿.md` 和最终 HTML 的唯一素材依据。

素材盘点表必须包含：
- 核心图：图号/位置、图中信息、适合讲哪一页、是否可直接截图使用
- 核心表：表号/位置、关键数字、支撑哪个 claim、是否需要重绘
- 关键公式：公式编号或段落位置、变量含义、是否需要在方法页重绘
- 关键实验：主实验、消融、泛化/迁移、效率、失败案例或局限证据
- 不可用素材：太小、不可读、装饰性、与主线无关或无法溯源的图片
- 重绘计划：哪些图表用 HTML table/SVG/CSS 重绘，重绘时保留哪些真实数字和标签

同时必须落地机器可读素材清单：

`outputs/{论文简称}_asset_manifest.json`

字段建议：
- `paper`: 论文简称、标题、年份、出处
- `assets`: 每个素材一个对象，包含 `id`、`type`（figure/table/formula/number/text_quote/redraw）、`source`（Figure/Table/Section/页码）、`page`、`caption_or_context`、`claim_supported`、`usable`、`reason_if_not_usable`、`crop_path`、`redraw_required`、`key_values`
- `numbers`: 关键数字列表，包含 `value`、`metric`、`condition`、`source`、`meaning`
- `uncertain_items`: 无法确认但可能需要追查的内容

原则：
- 进入最终 HTML 的每个图片、表格、数字卡、公式块、流程图都必须对应 `asset_manifest.json` 中的一个 `id`。
- 如果素材没有可靠来源，只能进入 notes 的“不确定/待核对”，不得进入观众可见结论。

组会页面结构必须包含：
- 整体叙事主线：痛点 -> 旧方法不足 -> 核心设计 -> 证据 -> 批判 -> 迁移启发
- 每页页面类型：定位页/动机页/方法总览/模块拆解/主实验/消融/批判/总结
- 必须包含首页幻灯片和结束幻灯片：首页展示论文标题、作者、机构、出处/年份、任务和核心贡献；结束页展示谢谢/Q&A/重要参考资料。
- 首页必须是 PPT 封面模板，不是内容页：logo/机构标识、英文标题、中文副标题或汇报主题、作者/机构、汇报人、日期、底部主题色信息条。
- 每页核心 claim：本页只证明或解释一个主要结论
- 每页视觉依据：来自素材盘点表中的哪张图、哪张表、哪个公式或哪个重绘对象
- 每页讲解时间：保证总时长符合用户需求或默认组会时长

同时必须落地机器可读页面计划：

`outputs/{论文简称}_deck_plan.json`

每页字段建议：
- `slide_no`
- `page_type`
- `title`
- `claim`
- `evidence_ids`
- `layout_pattern`
- `visible_text_budget`
- `visual_role`
- `speaker_notes_focus`
- `source_coverage`

原则：
- `evidence_ids` 必须来自 `asset_manifest.json`。
- `layout_pattern` 必须来自 [layout_patterns.md](layout_patterns.md) 或写明等价版式。
- 普通内容页 `visible_text_budget` 建议 160-280 个中文字符；重点方法/实验页 220-420 个中文字符；超出必须拆页或放入 notes。
- 连续 3 页不得使用同一个 `layout_pattern`。

## 文件交付（默认）

完成内容后，默认落地以下文件到 `outputs/`：
- `{论文简称}_逐页逐字稿.md`
- `{论文简称}_HTML展示稿.md`（展示层内容与页面元数据）
- `{论文简称}_组会汇报.html`
- `{论文简称}_HTML_QA.md`（交付前检查结果）
- `{论文简称}_asset_manifest.json`（机器可读素材清单）
- `{论文简称}_deck_plan.json`（机器可读页面计划）

默认还应使用或生成以下中间资源：
- `outputs/{论文简称}_assets/`：裁剪后的 Figure/Table/公式图片，路径相对 HTML 文件可访问。
- 使用 `skills/paper-presentation/assets/ppt_html_template.html` 作为 HTML 基础模板。
- 使用 `skills/paper-presentation/scripts/inspect_pdf_assets.py` 探查 PDF 图表和 caption 候选区域。
- 使用 `skills/paper-presentation/scripts/crop_pdf_region.py` 进行 PDF 图表裁剪。
- 使用 `skills/paper-presentation/scripts/validate_html_deck.py` 进行自动 QA。

其中 `{论文简称}_HTML展示稿.md` 必须满足：
- 面向听众可读，不是口语逐字稿，也不是只给生成器看的提纲
- 第 1 页必须是封面页：完整论文标题、作者/机构、年份/会议、任务领域、汇报主题和一句话贡献
- 最后 1 页必须是结束页：谢谢 / Q&A / 重要参考资料，包含论文链接/代码链接/核心引用/讨论问题中的至少两类
- 每页必须包含非 bullet 字段：页面类型、本页核心判断、视觉元素、布局建议、来源依据
- 每页必须区分三层：观众可见层、讲者 notes 层、生成器元数据层
- 每页必须包含可见正文块：观众可见正文、关键要点、证据解读、图表标注、页尾 takeaway
- `图表设计说明`、`布局建议`、`讲者提示`、`页面目的`、`读图顺序` 不得进入 HTML 可见正文
- 普通内容页可见正文建议 160-280 个中文字符；方法/实验重点页建议 220-420 个中文字符；封面和总结页可更短
- 每页至少包含 2 个解释性文本块，不能只靠 3-5 条 bullet 支撑页面
- bullet 只作为辅助，每页 3-5 条；每条必须包含对象、结论和证据/机制中的至少两项，禁止空泛短句
- 每页视觉元素必须来自素材盘点表；若没有合适原图，必须明确使用表格重绘、流程图或对比卡片
- 每个图表、流程图或数字卡必须配论文事实型图表标注，解释变量、模块、真实数字或高亮区域；不得写页面设计说明
- 不得出现“本页要放什么/建议放什么”等占位指令
- 不得出现观众页元话语：`封面把`、`表格只保留`、`示意图把`、`读图时`、`听众应该`、`观众应该`、`这个结果支持`、`这一页`、`本页`、`页面用于`

`{论文简称}_组会汇报.html` 成稿必须满足：
- 无“第 X 页：”标题前缀
- 无正文重叠、溢出、遮挡
- 整体观感必须像日常组会 PPT，而不是网页 dashboard、论文讲义或 PDF 预览器
- 第 1 页是论文标题封面，而不是动机/方法/实验页
- 最后一页是谢谢 / Q&A / 重要参考资料页
- 正文不是短 bullet 堆叠；除封面/总结外，每页必须含解释段落和证据解读
- 至少 70% 页面含图表、流程图、公式块、对比卡片或重绘表格（非纯文字）
- 方法页必须有流程图或模块关系图；实验页必须有真实数字表格/重绘图/论文原图之一
- 所有数字可回溯到原论文内容
- 可直接浏览器全屏汇报，支持键盘翻页和页码显示
- 每页 notes 数据完整，可供演讲者查看或复制到逐字稿
- 每页必须有核心判断区（claim/takeaway），不能只是标题加 bullet
- 页面必须有主题视觉系统，禁止黑白文档式或普通 Markdown 风格
- 每个图表、表格、流程图或数字卡必须有来源标注和解释
- 可见解释必须是论文内容本身，不得把生成器说明、讲者提示、读图策略渲染到页面
- 方法页视觉必须贴合论文原图/公式/方法段落；泛化示意图不得作为核心视觉
- 核心论文图必须裁剪到 Figure/Table/公式区域或局部高亮；禁止用整页论文截图缩略图作为核心图
- 翻页/讲稿控件不得遮挡页码、来源、takeaway、正文或图表
- 不得使用悬浮底部醒目 takeaway 条遮挡内容；takeaway 应并入 claim、侧边结论卡、图表标注或 notes
- 不得出现大面积空卡片；高度超过页面 30% 的容器必须有真实正文、图表、表格或公式

`{论文简称}_HTML_QA.md` 必须包含：
- 页面数量检查：展示稿页数、HTML slide 数、逐字稿页数是否一致
- 结构检查：每页是否包含标题、正文、来源、页码、notes
- 视觉结构比例：含图表/流程图/公式块/对比卡片/重绘表格的页面比例
- 封面检查：第 1 页是否为完整论文标题封面
- 结束页检查：最后 1 页是否为谢谢 / Q&A / 重要参考资料页
- 内容边界检查：HTML 可见正文是否误放生成器说明、讲者提示或读图策略
- 内容密度检查：每页是否有观众可见正文、关键要点、证据解读、图表标注、takeaway
- 论文贴合度检查：方法页视觉是否来自论文原图、公式、变量或忠实重绘；是否存在泛化示意图冒充论文图
- PPT 观感检查：是否像日常组会 PPT，是否存在网页 dashboard/两栏大面板/通用 Evidence Visual 模板感
- 图片裁剪检查：核心 Figure/Table 是否裁剪到图表区域，是否误用整页论文截图
- 控件遮挡检查：翻页/讲稿按钮是否遮挡页面内容
- 结论条遮挡检查：是否存在橙色/黄色 takeaway 条覆盖主图、来源、页码、正文或表格
- 自动 QA 脚本结果：`validate_html_deck.py` 的输出摘要和未通过项
- 素材追溯检查：`asset_manifest.json` 是否覆盖最终 HTML 使用的图、表、公式、关键数字
- 页面计划检查：`deck_plan.json` 的 `evidence_ids` 是否都存在于 `asset_manifest.json`，版式是否至少 5 种且无连续 3 页重复
- 空白率/空卡片检查：是否存在明显空白大面板或无内容视觉容器
- 占位词检查：是否出现“本页要放/建议放/TODO/placeholder”等词
- 溢出风险检查：每页 bullet 数、最长 bullet、是否超过限制
- 人工/截图检查结论：是否可直接打开进行汇报
- 视觉设计检查：是否存在主题色、视觉层级、关键数字强调、非黑白文档风
- 证据真实性检查：随机抽查 3 个图表/数字是否可回溯到论文
- 未通过项和修复记录；若存在未通过项，不得标记为可交付

可选附加件：
- `{论文简称}_老师追问速查表.md`
- `{论文简称}_组会汇报.pptx`（仅当用户明确需要）
